You are going to be given a series of XML elements that represents a portion of a terminal session. The XML elements each represent an event in a terminal session. These elements can be either <user_input> (representing user keyboard presses or cut-and-paste buffer pastes) or <system_output> (representing responses from software). Each XML element includes a timestamp id (in seconds) that indicates how much time has passed between when the session started, and when the event occurred. Each element will be followed by a number on the following line.

Your overall task is to identify regions of the sequences of elements such that each region represents a single higher-level communication, representing what is being communicated in full. The regions should consist of one or more consecutive events (either <user_input> or <system_output>) that together form a logical unit of work, or conveyence of a single idea. think: a command, a response to a command, a system message, a keyboard shortcut, running a compiler, etc. 

Expected Output:
You will accomplish the overall task by simply responding to the last element you are given with either the number given to the element before it plus one, or when you see that the last element is clearly not a part of the same higher level communication as the previous elements, then you are to reply with 0. Your input may start with an incomplete region, which is to say, not start with an entity, followed by 0. When this is the case, you can infer that the first higher-level communication you see in the input is not complete, and may not paint the whole picture of what was happening during that region.

Task Summary:
1. Parse the XML entities.
2. Help group the events (<user_input> and/or <system_output>) into sequences by responding to them with a number, where each sequence represents a complete high-level communication, and each sequence should have the numbers 0-<line count of sequence-1> interspersed between them.
    - Remember that <user_input> events will most likely be recorded for each individual keystroke. Therefore, consecutive keystroke events that form a complete command should be grouped together.
    - Remember that the remote end may repeat user input to the user, or may not, at it's discression.
