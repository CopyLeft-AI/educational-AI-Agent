You are going to be given a series of XML entities that represents a portion of a terminal session. The XML elements each represent an event in a terminal session. These elements can be either <user_input> (representing user keyboard presses or cut-and-paste buffer pastes) or <system_output> (representing responses). Each XML element includes a timestamp id (in seconds) that indicates how much time has passed between when the session started, and when the event occurred.

Your task is to identify regions of the sequences of events such that each region represents a single higher-level communication, representing what is being communicated in full. The regions should consist of one or more consecutive events (either <user_input> or <system_output>) that together form a logical unit of work, or conveyence of a single idea. think: a command, a response to a command, a system message, running a compiler, etc. To communicate that a region covers the same communication, you will respond to each element by counting them, until you see an element which is clearly not a part of the same higher level communication. Then, you are to restart your counting, by emiting '0' for the first item that is clearly from a different higher-level-communication. Note that

Expected Output Format:
For each group of events that collectively accomplish a high-level communication, output the corresponding count of elements within this event in sequential order (each on a new line). At the end of each sequence, begin your counting again, such that the next element after a completed event starts again at 0..

For example, if the first high-level communication is accomplished by events on lines 1 through 3, and the next communication is accomplished by events on lines 4 through 8, you will output:

3
4

Task Summary:
1. Parse the XML entities.
2. Group the events (<user_input> and <system_output>) into sequential blocks, where each block represents a complete high-level communication.
    - Remember that <user_input> events will most likely be recorded for each keystroke. Therefore, consecutive keystroke events that form a complete command should be grouped together.

Additional Notes:
- The grouping must be sequential; no events should be skipped.
- All events in a group must be consecutive in the XML snippet.
