Your task is to identify higher level communications in your input stream, and judge whether a given element is a part of the prior higher level communication, or not.

Examples of the types of higher level communications we are trying to identify are:
a command,
a response to a command,
a system message,
a keyboard shortcut,
an escape sequence which redraws a menu item,
a series of backspaces correcting a typo

A higher level communication is represented in the input by of sequences of elements each preceeded by sequence numbers, where a complete communication starts with a '0' on a new line, followed by a single element on the next line. These elements can be either <user_input> (representing user keyboard presses or cut-and-paste buffer pastes) or <system_output> (representing responses from software). Each element includes a timestamp id (in seconds) that indicates how much time has passed between when the session started, and when the communication occurred. Following elements that are a part of the same higher level communication are each preceeded by incrementing positive sequence numbers indicating their place in the sequence until the higher level communication is complete. When a higher level communication is complete, it will immediately be followed by the '0' and the first entity which is a part of the next higher level communication. There are no end markers; every higher level communication's beginning (excepting the first) is so me other higher level communication's end.

You are going to be given a (possibly empty) series of elements that each represent a communication in a terminal session, each preceeded by sequence numbers on an empty line indicating which line number within a higher level communication the following element represents. After this list of elements and sequence numbers, you are going to be given a single element, for identification.  

Your task is to identify if the last entity you are given in the input set is a part of the yet-incomplete higher level communication immediately preceeding it.

You will accomplish your task by responding to the final element with either the sequence number immediately following the sequence number given to the prior element (indicating it is a part of the same higher level communication), or when you believe that the final element is clearly not a part of the same higher level communication as the preceeding sequence of elements, then you are to reply with '0'. If there was no preceeding sequences of elements provided, then you have been presented with the first element of a sequence, and should also to reply with '0'.

Your input may start with an incomplete higher level communication, which is to say, it not start with a '0'. When this is the case, you can infer that the first higher level communication you see in the input is not complete, and may not convey enough of the idea behind the higher level communication to assist you with contextualizing later elements.
Your input will end with two elements without a sequence number between them, or, if there was no previous higher level communication, a single element.
